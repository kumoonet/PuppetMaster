## 一、核心结论

1. **「傀儡」命名撞上学术前沿，且持续被验证**——Puppeteer Pattern（NeurIPS 2025，arXiv 2505.19591）与 PuppetMaster 同构：中央木偶师动态指挥专用傀儡，而非一个通用大模型干所有事。v1.0 简报的映射审计结论不变：5 项设计被学术验证正确，**其中升级点 1（难度路由）与升级点 2（Judge 位）已在 PuppetMaster Ver1.4.0 落地**。
2. **范式本尊升级了**——Evolving Orchestration 把编排从静态拓扑变成**可学习的序列决策**（REINFORCE，token −50%、调用数 −43%）。PuppetMaster 已吸收前半段（难度路由），**后半段（学习式多步调度）是下一个增量**，落地路径见 §六。
3. **A2A「发布但未成熟」**——v1.0 技术栈齐备（Protobuf / 签名 Agent Card / Task 生命周期 / mTLS+OAuth2），与 MCP、Agent Plugins 形成「工具 / 协作 / 分发」三层协议栈；但 judge 仲裁采谨慎派（实现混乱、生态多为演示）→ 挂观察，不预先接入。
4. **两个方向标注不采纳**：Agent 经济协议（AP2/x402）无结算场景；拍卖式路由在 5 傀儡规模下过设计。
5. **当前最实的三件事**：编排护栏薄包装（W1）、调度数据留档（W2，方案见 §六，**✅ 已随 Ver1.7.0 落地**）、批量交叉分批纪律（§七，针对新踩坑）。
6. **（v3.0.0）supervisor-worker 成 2026 生产默认，体系大方向被第三次验证**——Cognition/Anthropic/OpenAI/AutoGen/LangChain 五家收敛于 orchestrator+isolated-subagents；但前沿同时揭示三个此前未见的坑：**傀儡裁判同族自偏好**（5-25 点）、**路由只认硬失败漏软失败**（cascade verify-then-escalate 补齐）、**同族双交叉伪冗余**（Simchi-Levi 真异构前提）。三项均已在 PuppetMaster_Ver1.8.0 落地修正，详见 §十。

## 二、什么是 PuppetMaster：调度所的精确定义

**一句话**：PuppetMaster 是主模型（大模型）支配的**被动调度所**——主模型是木偶师，调度所是军火库 + 传令台，傀儡是手脚。

### 五步编排流程（与手册 4.3 一致）

```
① 理解需求   主模型读任务：干什么？（选命令）
   ↓
② 分派任务   主模型按傀儡长处选 --model（route 给建议，仅供参考）
   ↓
③ 傀儡干活   并行调 free_models.py —— 傀儡只执行，不判断、不决策
   ↓
④ 收集判断   主模型收集结果 → 交叉验证 / judge 仲裁 / 兜底
   ↓
⑤ 输出结论   不足 → 回 ② 重新分派（再分配循环）；足够 → 输出最终结论
```

### 三个精确化（防概念漂移）

| 直觉说法 | 精确表述 | 为什么重要 |
|---------|---------|-----------|
| 「调度所分派任务」 | **主模型分派，调度所只承载**——free_models.py 是纯 CLI，无常驻服务、无调度逻辑；「分派给谁」100% 由主模型决定 | 调度所可被任何壳（WorkBuddy/千问办公/定时任务）平等复用，正因为它不做决策 |
| 「调度所分拆任务」 | **分拆在主模型侧（①②步）**，调度所只提供 13 个任务型命令 + models.json 名册 | 分拆质量决定编排质量，这是主模型的职责，不能外包给工具 |
| 「傀儡干完交结论」 | **傀儡输出只是参考素材**——判断、校验、再分配、最终结论永远属主模型（判断权红线；输出密集型产出强制校验后采纳） | 与 Evolving Orchestration 的边界一致：学习的是调度策略，不是把判断权交给傀儡 |

**学术坐标**：Evolving Orchestration 论文里的木偶师 = **可学习的调度策略**；PuppetMaster 当前的木偶师 = **主模型 + 人工口诀**（选型口诀/分派策略 5 条）。§六 的调度数据，就是把「人工口诀」进化为「实证调度表」乃至「学习式策略」的原料。

### ❌ 不采纳（记录理由）

- **AP2 / x402 支付协议**：无 Agent 结算场景，接入即过设计。
- **反向拍卖 / 协商式路由**：5 傀儡不构成竞价市场；周体检 + 经验选型仍是局部最优。规模 >15 傀儡再议。
- **A2A 接入**：机内子进程范式（PuppetMaster）与机间智能体范式（A2A）是尺度差异不是替代；无机间协作需求前不预先接入（judge 仲裁采谨慎派佐证）。
- **（v3.0.0）GEPA 提示自变异**：每 15 次调用评估 + 提示变异 + holdout 回放（Hermes Agent，ICLR 2026 Oral，ETH 复现 33-38% 提升）——演化的提示难事后审计，且免费 8B 级模型做不了高质量变异评估；重复任务收益真实，但个人体系引入的审计成本 > 收益。**不采纳**。
- **（v3.0.0）Mimosa 式 meta-orchestrator**：工作流拓扑自动合成 + judge 反馈迭代（ScienceAgentBench 43.1%）——面向科研长任务，10 傀儡规模下口诀+实证调度表已够用（最小够用纪律）。**不采纳**。
- **（v3.0.0）蒸馏学生模型 + OOD 检测**：需训练资源与评测基础设施，超出个人体系。**不采纳**。
- **（v3.0.0）企业网关层（Portkey/Kong/LiteLLM 等 22+）**：纯 CLI 无网关（v1.5.0 已验证：有 Bash 就不用 MCP/常驻服务）。**不采纳**。
- **（v3.0.0）讨好偏差注入检测**：往评测集塞已知坏输出测裁判真阴性率——judge 已降低频可选档，成本 > 收益。**不采纳**。

## 六、调度数据：怎么攒，怎么实现（W2 实现方案）

### 目标

把当前「主模型 + 人工口诀」的木偶师，进化为「实证调度表」乃至「学习式策略」。数据元组对齐 Evolving Orchestration 的训练信号：

```
记录 = (任务特征, 调度决策, 执行者, 执行成本, 质量收益)
训练信号 = 质量收益 − λ × 执行成本   （对应论文 REINFORCE 的 r − λ·C）
```

### 方案 A（推荐）：脚本自动留档 + 主模型事后评分 —— ✅ 已随 Ver1.7.0 落地

**原理**：客观字段（谁干的、花了多久、成没成）由脚本自动记，绝不靠自觉；主观字段（干得好不好）由主模型在任务收尾时补记——机器记事实，人/主模型记判断，各守一边。

**第一步：自动调度日志**（free_models.py 加 ~30 行，纯标准库）

每次命令执行后追加一行 JSON 到 `调度档案.jsonl`：

```json
{"ts": "2026-08-23T14:30:00", "task": "classify", "model": "agnes-2.5-flash",
 "text_len": 4200, "out_len": 45, "elapsed_ms": 1260, "exit_code": 0,
 "retry": 0, "group": "batch-20260823-新闻分类"}
```

新增可选参数 `--group <任务组名>`：批量分派时同名归组，事后可按组聚合评估（这是「任务 → 调度序列」的关键，对齐 P1 的序列决策视角）。

**第二步：事后质量评分**（新增命令 `rate`）

```bash
python free_models.py rate batch-20260823-新闻分类 4 "分类准确，漏1条电商"
```

追加写入同一档案（`type: "rating"` 行），按 `group` 关联。评分口径 v1.8 起补全 5 档行为定义：**1=错误输出污染下游 / 2=格式或事实硬伤 / 3=合格 / 4=好 / 5=优**——依据 LLM-as-Judge 窄量表+行为锚定研究（模糊分档导致评分不可复现；2026-08-28 调研中 summarize 打 2 分即为无定义时的拍脑袋判例）。

**第三步：定期聚合 → 实证调度表**（≥50 条记录后；调度档案现约 45 条，接近触发）

一次性聚合脚本（或让主模型直接读 jsonl 分析）输出四张表：

1. **傀儡 × 任务型成功率矩阵**——哪个傀儡干哪类活最稳（验证或推翻选型口诀）
2. **难度判定命中率**——route 判「简单」的任务实际用轻量傀儡的合格率（验证难度路由准不准）
3. **成本分布**——各傀儡 × 任务型的耗时/重试分布（给护栏的超时阈值提供实证依据）
4. **失败模式注册表（v1.8 新增）**——`exit_code≠0` 与 `rate 1-2 分` 记录聚合为「模型 × 任务 × 失败类型」三列表（对齐 Socratic-SWE「解题轨迹即改进原料」思想），把散落判例（Qwen2.5-7B tags 乱码 / 推理模型 content 为空 / 魔搭空壳 / glm 批量截断 / agnes-2.5 长任务空输出）结构化为可查询资产。**寄生式，不额外造数据。**

产出物：《实证调度表 v1》→ 回写手册 4.3 分派依据表，**用数据替代口诀**。

**第四步（条件触发，可能永远不需要）**：若实证调度表运行后仍有 >15% 的分派失误，再评估引入真正的学习式调度（规则表可能已是 5 傀儡规模的最优解——最小够用纪律）。

### 方案 B（备选）：纯流程留档

不改脚本，手册规定批量分派时主模型输出调度表并记入档案。**不推荐为主线**——依赖自觉必漏记，且非结构化无法统计。仅作方案 A 未落地前的过渡：今天起，批量分派（≥3 轮）时主模型在交付里附调度表，我代为记入 `调度档案.md`。

### 攒数节奏

- 不造任务攒数据——**寄生在日常使用里**（每次 MSE 加工层、每次批量分类自然产生）
- 按当前使用频率，预计 1-2 周达 50 条门槛
- 纪律一句话：**批量分派必带 --group，任务收尾必 rate**（2026-08-28 范式调研调度漏带 --group，已补 meta 记录入档案作反面判例）

## 七、扬长避短：新踩坑的根因与四层规避（W3 方案）

### 根因（先追因再谈规避）

2026-08-23 实测：45 行列表双交叉分类，agnes-2.5 全量输出，**glm-4-flash 输出截断**（分段重测仍截断）。这不是网络/限流问题，是**输出预算超限**——45 行分类结果 × 每行约 10 token ≈ 超出 glm-4-flash 的输出配额。暴露的组合场景是「**长输入 × 长输出**」：glm 的长处在输入侧（128K 窗口），短处恰在输出预算。

## 十、2026-08 扫描增量（v3.0.0 新增章）

> 2026-08-28 四方向扫描（WebSearch：LLM 路由 / 多 agent 编排 / LLM-as-Judge / 自我进化，13 条前沿进展）→ 傀儡 extract 加工（agnes-2.5，4 分准确）→ 主模型综合与吸收决策。本章是 PuppetMaster_Ver1.8.0 四项变更的依据链。

### 1. cascade verify-then-escalate：failover ≠ cascade

LobeHub 417 任务实测 benchmark：cascade 架构 = classify → answer → **verify** → escalate ⟲（升级边回环），核心主张"在最便宜的、可被验证答对的模型上作答，验证失败才升级"。三阶梯数据：wide（deepseek-v4-flash→Opus5）cascade 95.7% vs 92.3% 且成本 1/4；claude 阶梯 +4.3% 但每条多花 $0.00097（验证不免费时倒贴）；deepseek 阶梯 +2.9% 成本持平。**结论：无通用价格比阈值，cascade 划算与否取决于「验证是否便宜」×「顶层是否真更好」**。理论侧 RLCascadeRouter（arXiv 2608.15817）证明预测损失≠决策损失， Quality-Estimator-Free 直接优化性能-成本目标。

**PuppetMaster 映射**：failover 只认硬失败（退出码/超时/空输出），静默错误（成功返回但答错）检测不到 → **分派策略⑦ verify 软失败升级**：A 类判断输出与预期模式不符（类别外溢/格式可疑/边界模糊/与事实冲突）不当作成功，升级主模型重做。本体系验证≈免费傀儡 vs 升级主模型，极端价格比天然适合 cascade。

### 2. LLM-as-Judge 五大具名偏差量化表

| 偏差 | 效应量 | 缓解 | PuppetMaster 落地 |
|------|--------|------|------------------|
| Position（A 位占优） | 10-15pt 胜率摆动（Zheng 2024） | 双序跑一致才采纳；提示词"平等考虑"实测无效（偏差在自回归解码） | 主模型**实质仲裁**（直接判哪个正确，非 A/B 格式题）；judge 可选档双序 |
| Self-preference（同族溢价） | 5-25pt（Zheng 2024） | 跨家族裁判 | **同族裁判禁令**（注意事项 16）：判例 1 旧主裁判 glm 与候选同族、判例 2 MSE agnes-2.0 裁判与 agnes-2.5 候选同族——两处现存偏差已废 |
| Verbosity（长者高估） | 15-30pt（Wang 2023） | 长度中性 rubric | judge 为 A/B 对比无 rubric 打分，影响小；主模型实质判断不受影响 |
| Format（表层特征过权） | 5-15pt | 同内容换格式重打分 | 不适用（无格式化评分） |
| Calibration drift | 小版本升级 3-8pt 漂移 | 换裁判当迁移处理，重跑人工标注集 | 裁判已收敛为主模型（无版本漂移面） |
| Agreeableness（讨好） | 真阴 <25%（类别不平衡） | 注入坏输出检测 | judge 低频可选档，成本>收益，**不采纳** |

**校准协议要点**（rate 评分借鉴）：200-500 例人工金集 + kappa>0.60；few-shot 锚定 3-5 例 > 纯指令；1-4 窄量表带行为锚定。**落地：rate 口径补全 5 档行为定义**（1=污染下游 / 2=格式或事实硬伤 / 3=合格 / 4=好 / 5=优）。

### 3. Simchi-Levi 集中决策定理 + 真异构前提

MIT Simchi-Levi：**无新外部信号时，任何委托式无环网络在决策论上被集中式贝叶斯决策者支配**。为「判断权归主模型」红线提供理论背书——但前提是傀儡须提供**真异构信号**，否则多模型交叉是伪冗余。**落地：批量>20 行 classify 主链 agnes-2.5+agnes-2.0（同族）改 agnes-2.5+Qwen3-8B（跨族）；六维价值⑥补"真异构"前提**。

附：架构免疫性确认——PuppetMaster 傀儡零 peer 通信，天然免疫 hub 级联感染（"From Spark to Fire"：单个假信息可 100% 感染 hub-and-spoke 全系统）；judge 是唯一"傀儡读傀儡"路径，v1.8 改主模型后该感染面同步关闭。

### 4. 自我进化三路径：只吸收寄生式一条

| 路径 | 代表 | 判定 |
|------|------|------|
| 源码级自改 + 单调保证 | MOSS + Ratchet（2026-05） | 不采纳（脚本自我修改审计成本高） |
| 技能结晶 | GenericAgent（执行路径→可复用 Skill） | 观察项——WorkBuddy SkillManage 生态契合，遇新复用模式再落 |
| 轨迹→结构化失败模式 | Socratic-SWE（Agent Skill Registry，SWE-bench 50.4%） | **✅ 吸收：失败模式注册表（寄生式，§六第三步第 4 表）** |

补充：Anthropic 研究架构（lead agent 规划 + 子 agent 并行收集）超单 agent 90.2%，支持体系并行分派策略④；"模型选择是入场券，编排拓扑是一等优化目标"——收编工作暂缓（2026-08-28 用户拍板：不免费的不收编），精力转向拓扑优化（v1.8 三项拓扑修正即此方向）。
