# 免费 / 高性价比 AI 模型 API 接入指南（实测版）

> **版本**：Ver1.5 · 2026-08-23（新增「七、编程类省 Token 实测」章节——含测试设计/两轮执行过程/实测数据表/结论与决策，原七~顺延为八；Ver1.4 保留备份；本章节由傀儡 agnes-2.5-flash 代写初稿、主模型校准落位）
> **（2026-08-29 同日补说明，不升版）**：随 PuppetMaster Ver1.8.0/1.8.1 同步——六维⑥仲裁归属改主模型实质仲裁 + 真异构前提；六章末新增「编排纪律速查」（验收标准/试跑/分层原则/不做链式加工，摘自手册 §4.3.1）。
> **口径**：稳定性优先于价格。免费 ≠ 可用，便宜 ≠ 划算——免费但慢/不稳 = 不可用。本指南同时覆盖**免费**与**高性价比付费**模型，付费档标注价格（价格变动快，以官网为准）。
> **傀儡观（Ver1.3）**：本指南 = 子代理傀儡池选型手册。**找的不是"免费模型"，是"干四类基础活（分类/打标/摘要/改写）、稳定可支配的傀儡"**——免费只是福利，稳定才是命。**只收真免费**（消耗魔粒/积分/限时额度的模型不收编，见文末备份附录）。已收编傀儡（脚本 `free_models.py` 可直接调用）：`glm-4-flash` / `agnes-2.5-flash` / `agnes-2.0-flash` / `lite` / `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free`。
> **实测项**：标注「✅实测」为当日真实 API 调用结果（含响应时间）；「📚来源」为公开资料核实。

## 六、省 Token 实测与六维增量价值（2026-08-23 真实计费口径）

> **本体系的灵魂**：省 token 只是副产品，真正的价值是**释放主模型的注意力**——让多个免费模型当你的并行手脚，主模型只读加工后的精华、只做判断。本节用真实 API 计费口径（`usage.prompt_tokens` / `completion_tokens`）实测得出，直接指导分派策略（见「七、注意事项」第 13 条 + PuppetMaster 手册 4.3 分派策略）。

### 1. 实测方法与过程（2026-08-23，真实 API 计费口径）

**测试设计**：对比「主模型直读原文」vs「傀儡加工后主模型只读结果」，8 类傀儡干活类型各测一轮（classify / tags / route / summarize / extract / translate / proscons / explain），覆盖输入密集与输出密集两类。全部以 `glm-4-flash` 实测（加工主力），同一批输入样本跑完 8 类，保证横向可比。

**执行步骤**：
1. 准备输入样本：取一段有信息密度的长文（财经/科技类新闻段落，含可分类、可打标、可摘要、可提取要素的内容）
2. 主模型直读基线：模拟主模型直接读原文，记录输入 token（= 原文 token 数）
3. 傀儡加工：对同一输入跑 8 类任务，每类读取 API 返回的 `usage.prompt_tokens`（输入）与 `completion_tokens`（输出）
4. 加工后主模型只读结果：主模型读的输入 = 傀儡的输入 + 傀儡的输出（total = prompt + completion）
5. 计算省幅：`省% = (直读 token − 加工后 total) / 直读 token × 100%`，分别统计省 prompt（直读原文 vs 傀儡输入）与省 total（直读原文 vs 加工后主模型读的总量）

**计费口径说明**：读 API 返回的 `usage.prompt_tokens` / `completion_tokens`，是**真实计费口径**而非估算——省幅数字可直接换算成钱/窗口占用。total = prompt + completion。

**各任务输入→输出形态**（决定省幅方向）：

| 任务 | 输入 → 输出形态 | 省幅特征 |
|------|---------------|---------|
| classify | 全文 → 2-5 字类别 | 输出极短，输入输出双省，最狠 |
| tags | 全文 → 3-5 个标签 | 输出短，双省 |
| route | 全文 → 难度 + 推荐傀儡 | 输出短，双省 |
| summarize | 全文 → 3-5 句摘要 | 输出中等，total 仍大幅省 |
| extract | 全文 → 时间/主体/事件/金额/数字 | 输出比输入长时 **prompt 倒挂**（但 total 仍省） |
| translate | 全文 → 译文 | 输出接近输入长度，倒挂 |
| proscons | 全文 → 利/弊分列 | 输出较长，倒挂 |
| explain | 全文 → 大白话解释 | 输出最长，**倒挂最狠** |

**token 计算实例**（以 summarize 为参照）：原文 5000 token 直读 = 主模型吃 5000；傀儡先吃 5000（prompt）+ 吐 300（completion）→ 主模型只读 300+提示 ≈ 800。加工后主模型读的总量 ≈ 傀儡输出，省幅巨大。输出密集任务反直觉点在于：**傀儡自己吃掉的那份输入也要算账**——prompt 倒挂意味着傀儡输入 + 输出 > 原文，但主模型省下的生成量（completion）仍然划算。

**踩坑全过程（真实记录）**：
- **坑 1 · 连续调用触发 429 限流**：批量实测连续调用 8 轮后，glm-4-flash 触发限流（HTTP 429）——免费模型有 RPM 上限，连续高频调用必触发
- **坑 2 · SystemExit 静默退出**：脚本 `fail()` 抛 `SystemExit`，被 `except Exception` 漏捕 → 进程静默退出、无报错、无退出码，排查极难。**修复**：改用 `except BaseException` 捕获 + 对 429/5xx 加重试 + 循环间 sleep 2-4s
- **坑 3 · heredoc 中文脚本不稳定**：Git Bash 下 heredoc 传中文内容偶发编码问题，改用 Write 工具写脚本文件 + `-u` 无缓冲运行才稳定
- **坑 4 · summarize 管道误判**：编程式调用（subprocess）时 stdin 变管道，脚本 `not sys.stdin.isatty()` 误判读空 → 空输出。**修复**：位置参数优先，空输入明确报用法（exit 2）

这些坑已固化为纪律：「七、注意事项」第 13 条（节流）+ PuppetMaster 手册注意事项第 12/13 条。

### 3. 均值结论

- **输入密集型（4 类：classify / tags / route / summarize）**：省 total **78%**，省 prompt 46%——真省 token 的活。
- **输出密集型（3 类：translate / proscons / explain；extract 实测也倒挂，归此列）**：省 total **40%**，但 prompt 倒挂（傀儡输出比输入长）——省的是主模型的生成（completion），不是输入。
- **全类型省 total 64%**；省 prompt 因类型差异大（输入密集 46% / 输出密集 -74%）**不可用一个数概括，看类型**。
- **短文本（<100 字）不加工**：加工成本 > 收益时不值得，主模型直接读原文。

|------|------|------------------|
| ① 省 token | 全类型 total 均值省 64%；输入密集省 78%、输出密集省 40% | 省的是"量"与"窗口"——防限流、防上下文窗口不够（实测数据见上） |
| ② 并行干活 | 5 傀儡 = 5 子代理同时跑 | 主模型不排队，批量任务时间减半（PuppetMaster 池内 5 个真免费傀儡） |
| ③ 主模型专注度 | 只读加工后精华，不淹没在原文噪音 | 注意力不被 10 条官网导航式噪音稀释（MSE 实测：summarize 一句点破"全是 B2B 官网页面"） |
| ④ 防限流 | 各免费 API 独立窗口互不挤占 | 连续批量调用不触发单一模型 429（实测连续 8 轮触发限流教训） |
| ⑤ 窗口容量 | 原文堆进上下文会互相污染 | 加工后省窗口，长会话不爆上下文 |
| ⑥ 异构视角 | 多模型交叉验证 + 仲裁 | 防单模型偏见，关键判断更抗错（双交叉不一致→**主模型实质仲裁**，v1.8——傀儡裁判会给同族输出 5-25 点系统性溢价，LLM-as-Judge 研究判例；**前提：交叉必须真异构，同族交叉是伪冗余**） |

> **一句话**：省 token 只是第 1 维，后 5 维（并行 / 专注度 / 防限流 / 窗口 / 异构）是更根本的价值——**傀儡池的本质是"注意力解放器 + 并行手脚"，不是"省钱工具"**。所有分派策略都从这个核心推导：输出密集产出必须主模型校验后采纳、批量默认并行、关键判断强制双交叉（不一致→主模型实质仲裁）。

### 5. 编排纪律速查（v1.8.1 摘录，完整版见《PuppetMaster_Ver1.8.1.md》§4.3/§4.4）

| 纪律 | 一句话 |
|------|--------|
| 仲裁归属 | 双交叉不一致 → **主模型实质仲裁**（直接判哪个正确，非 A/B 格式题；傀儡裁判同族自偏好已废） |
| verify 软失败 | 输出与验收标准不符 ≠ 成功（类别外溢/格式可疑/与事实冲突）→ 升级主模型重做；failover 管硬失败，verify 管软失败 |
| 命令级验收标准 | 每个命令定义 expected_output——结构自检脚本管（行数/非空/截断），内容验收主模型管 |
| 批量先试跑 | >20 条或 >5 轮调用，先跑 3-5 条样本验证，通过再放量（单条合格 ≠ 批量合格） |
| 分层原则 | 确定性路径写死（failover 链/阈值/验收标准），判断性决策放权（主模型）——规则能覆盖的写死，需要理解的放权 |
| 不做链式加工 | 多步加工各步独立取原文、结果并列汇总——避免"前环节产出塞进后环节上下文"的链式 token 膨胀 |

## 七、编程类省 Token 实测（2026-08-23，真实计费口径）

> **本章由傀儡 agnes-2.5-flash 代写初稿、主模型校准落位**——正好是 PuppetMaster 哲学的一次实践：傀儡写、主模型校验。
> 📎 **测试脚本**：`bench_coding.py`（短任务）/ `bench_coding2.py`（长任务），保留可复测。

### 1. 测试设计

- **测试时间 / 口径**：2026-08-23，真实 API 计费（`usage.prompt_tokens` / `completion_tokens`），与第六章同口径
- **测试目的**：验证"主模型直写"vs"傀儡写 + 主模型校验"两种模式在**编程任务**上的 token 成本差异
- **任务类型**：短任务（排序函数 / 爬虫片段 / 数据处理）+ 长任务（100 行代码修 bug / 加功能）
- **对比路径**：A = 主模型直写代码；B = agnes-2.5-flash 写代码 + 主模型只读校验
- **轮次设计**：两轮对照——第一轮用 glm-4-flash 当主模型代理（**基线错误，已废弃**）；第二轮用真实主模型 deepseek-v4-flash-0731（有效）

### 2. 执行过程与踩坑

**第一轮（已废弃）**：以 `glm-4-flash` 作为主模型代理，发现傀儡模式全面巨亏（-90%~-362%）。后续排查确认根因：**免费傀儡当主模型基线会系统性低估主模型生成成本**——glm-4-flash 生成便宜、输出短，直写基线被压到极低，傀儡绕路成本自然显得巨亏。该轮数据不可信，予以废弃。

**第二轮（有效）**：更换真实主模型 `deepseek-v4-flash-0731`（用户当前 WorkBuddy 会话驱动模型），结论翻盘。同时暴露 4 个踩坑：

| 踩坑 | 现象 | 处理 |
|------|------|------|
| agnes-2.5 推理模型长任务 `reasoning` 吃满 `max_tokens` → content 空输出（`text_tokens=0`） | 输出为空，校验无从谈起 | `max_tokens` 加大至 4000/6000 重试 |
| glm-5.2 免费额度耗尽 | 返回 403 Free quota exhausted | 更换模型（glm-5.2 已从 models.json 移除） |
| 校验输出 `max_tokens=200` 触顶 | 校验结论被截断（⚠️ 而非 ✅/❌） | 校验 `max_tokens` 调至 ≥300 |
| 免费傀儡当主模型基线 | 直写成本被低估 → 错误结论 | 基准测试必须用真实主模型 |

**第一轮（glm-4-flash 代理，已废弃）**

| 任务 | 直写 | 傀儡+校验 | 省幅 |
|------|------|-----------|:---:|

**第二轮（deepseek-v4-flash-0731 真实主模型，有效）**

| 任务 | 直写 | 傀儡+校验 | 省幅 | 结论 |
|------|------|-----------|:---:|------|

| 爬虫片段 | 475 | 684 | -44% | 直写优 |
| 数据处理 | 269 | 724 | -169% | 直写优 |
| 长代码修bug | 5887（completion 5000 触顶） | 4504 | **+23.5%** | **傀儡真省** |

> 负值 = 傀儡模式消耗更多 token（倒挂）；只有长代码修 bug 一项在真实主模型下翻转为正。

### 4. 核心结论

1. **主模型生成越贵，傀儡写代码越划算**——completion 价差是决定因素，不是 token 数
2. **短任务（排序/爬虫/小函数）无论主模型是谁都倒挂**——傀儡绕路成本 > 省幅，不值得
3. **长代码任务主模型 completion 预算吃紧（>3000）时，傀儡可真省**（修 bug +23.5%）
4. **判定准则**：直写 completion 预算吃紧的活适合傀儡，否则主模型直写
5. **基准测试必须用真实主模型**——免费傀儡当基线会系统性低估直写成本，得出错误结论

### 5. 最终决策（用户，2026-08-23）

> **未来只要涉及代码（写/改/修bug/加功能）一律主模型直写，傀儡池不碰代码。**
> 即使长代码实测傀儡可真省 +23.5%，也不采用——**代码质量可控优先于省 token**（主模型写 = 一次到位 + 质量可控；傀儡写需校验 + 返工，省 23% 不值）。

已同步至 PuppetMaster 手册 4.3 分派策略第 6 条 + 判断权红线（代码任务默认主模型直写）。

## 八、注意事项

1. **免费 ≠ 稳定**：免费档普遍限流（RPM/RPD），高峰会排队，实测为准。
2. **高性价比 ≠ 便宜**：DeepSeek ¥1/百万输入是当前性价比标杆；付费前先小额测试稳定性（如高峰 503）。
3. **账户余额**：智谱等平台免费模型可调，但付费模型需充值（无余额报 1113）。
4. **代理问题**：Gemini、GitHub Models 需代理；OpenRouter 实测国内可直连（无需代理）。
5. **数据训练**：Mistral Experiment 档、部分平台免费档会拿你的数据训练，敏感数据慎用。
6. **政策变动快**：免费额度/价格随时调整，以官网最新为准。
7. **价格口径**：文中价格为 2026-08 核实或公开资料，付费价格变动快，调用前以各平台官网定价页为准。
8. **地区封锁（实测）**：Groq（console/api）与 Cerebras（cloud/inference）对大陆 IP 直接 403 封锁，需代理；Cerebras Cloudflare 拦截页明确标注禁止 CN 地区（2026-08-22 实测）。指南中标注「⚠️ 需代理」的平台均无法国内直连。
