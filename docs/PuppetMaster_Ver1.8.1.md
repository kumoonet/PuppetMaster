# 子代理免费模型工具 · 使用手册

**Ver1.8.1 · [KuMoo] · 素观设计 SuGuan** · 2026-08-29

## 一、这是什么

把**免费模型收编为子代理傀儡**——可随时支配、干基础活（分类/打标/摘要/改写/问答/**难度路由/仲裁/翻译/利弊/解释/提取**）的稳定 API 工具。供 WorkBuddy 子代理、skill、定时任务直接调用（纯 CLI，无常驻服务）。

> 背景：这些模型在 WorkBuddy 主对话窗口里都不可用——WorkBuddy 的 agent 请求体约 600KB+（完整系统提示+全部工具定义），讯飞 Lite 8K 窗口装不下（报 10003），智谱对大请求体触发限流（429）。**绕开对话窗口、用脚本发轻量请求，才是它们的正确打开方式。**

> 傀儡观：**找的不是"免费模型"，是"干基础活、稳定可支配的傀儡"**——免费只是傀儡的福利，稳定才是傀儡的命。

> 范式锚点（v1.4）：本体系与学术前沿 **Puppeteer Pattern**（NeurIPS 2025，中央编排者动态指挥专用傀儡）同构；难度路由与 Judge 仲裁依据 **Dynamic Model Routing** 综述（arXiv 2603.04445）落地；调度数据方案与扬长避短详见同目录《Puppeteer范式研究简报_Ver3.0.0.md》（§六调度数据方案 / §七扬长避短）。
>
> 范式锚点（v1.8 补，依据 2026-08-28 四方向范式扫描，13 条前沿进展）：**级联路由 cascade**——answer→verify→escalate⟲ 回环，在最便宜的、可被验证答对的模型上作答，验证失败才升级（RLCascadeRouter arXiv 2608.15817：路由建模为 MDP，预测损失≠决策损失；LobeHub 417 任务实测：验证便宜时 cascade 稳赚，无通用价格比阈值）；**LLM-as-Judge 五大具名偏差**——position（10-15pt）/ verbosity（15-30pt）/ self-preference（同族溢价 5-25pt）/ format（5-15pt）/ calibration drift（3-8pt），缓解=双序跑+跨族裁判+人工金集校准（kappa>0.60）；**Simchi-Levi 集中决策定理**（MIT）——无新外部信号时，任何委托式无环网络在决策论上被集中式贝叶斯决策者支配，为「判断权归主模型」红线提供理论背书，**前提是傀儡须提供真异构信号，否则交叉纯属浪费**。

## 二、核心思考与实践（省 token 实测 + 六维增量价值）

> **本体系的灵魂**：省 token 只是副产品，真正的价值是**释放主模型的注意力**——让多个免费模型当你的并行手脚，主模型只读加工后的精华、只做判断。本节是 2026-08-23 用真实 API 计费口径（`usage.prompt_tokens` / `completion_tokens`）实测得出的核心结论，直接指导分派策略（见「五、能力总览」4.3）。
>
> 📎 **具体测试结论与过程详见**：《免费AI模型API接入指南_傀儡池.md》第六章「省 Token 实测与六维增量价值」+ 第七章「编程类省 Token 实测」——含实测方法与过程详解（测试设计/执行步骤/各任务输入输出形态/token 计算实例/四个踩坑全过程）、8 类任务实测数据表、编程类两轮实测（glm-4-flash 错误基线废弃 / deepseek 真实主模型结论翻盘）、均值结论、六维增量价值、代码任务决策。本手册只保留结论摘要与策略推导。

### 2.1 省 token 实测（8 类任务，真实计费口径）

对比「主模型直读原文」vs「傀儡加工后主模型只读结果」：

| 任务 | 类型 | 省 prompt | 省 total | 说明 |
|------|------|:---:|:---:|------|
| classify | 输入密集 | 97% | 94% | 全文 → 2-5 字类别，最狠 |
| tags | 输入密集 | 92% | 92% | 全文 → 3-5 标签 |
| route | 输入密集 | 84% | 90% | 全文 → 难度+推荐 |
| summarize | 输入密集 | 59% | 82% | 全文 → 3-5 句 |
| extract | 输入密集 | -104% | 31% | **prompt 倒挂**（输出比输入长），但 total 仍省 |
| translate | 输出密集 | -38% | 52% | 倒挂，total 仍省 |
| proscons | 输出密集 | -68% | 42% | 倒挂，total 仍省 |
| explain | 输出密集 | -115% | 27% | 倒挂最狠（大白话解释膨胀），total 仍省 |

**均值结论**：
- **输入密集型（4 类）**：省 total **78%**，省 prompt 46%——真省 token 的活
- **输出密集型（3 类）**：省 total **40%**，但 prompt 倒挂（傀儡输出比输入长）——省的是主模型的生成（completion），不是输入
- **全类型省 total 64%**；省 prompt 因类型差异大（输入密集 46% / 输出密集 -74%），**不可用一个数概括，看类型**
- **短文本（<100 字）不加工**：加工成本 > 收益时不值得，主模型直接读原文
- **（v1.8 补充实测，2026-08-28 范式调研调度）**：概括类任务（summarize/tags）对长调研素材压缩过度（2 分，只列表面抓不住范式要点）；事实型素材 extract 可靠（4 分，数字提取核对无误）——**主模型的深层综合不能被傀儡替代**，印证策略③

### 2.2 六维增量价值

| 维度 | 内容 | 为什么根本 |
|------|------|-----------|
| ① 省 token | 全类型 total 均值省 64% | 省的是"量"与"窗口"，防限流、防窗口不够 |
| ② 并行干活 | 5 傀儡 = 5 子代理同时跑 | 主模型不排队，批量任务时间减半 |
| ③ 主模型专注度 | 只读加工后精华，不淹没在原文噪音 | 注意力不被 10 条官网导航式噪音稀释 |
| ④ 防限流 | 各免费 API 独立窗口互不挤占 | 连续批量调用不触发单一模型 429 |
| ⑤ 窗口容量 | 原文堆进上下文会互相污染 | 加工后省窗口，长会话不爆上下文 |
| ⑥ 异构视角 | 多模型交叉验证 + 仲裁 | 防单模型偏见，关键判断更抗错（**v1.8 前提：交叉必须真异构——跨家族才提供独立信号，同族交叉是伪冗余**） |

**一句话**：省 token 只是第 1 维，后 5 维（并行/专注度/防限流/窗口/异构）是更根本的价值——**傀儡池的本质是"注意力解放器 + 并行手脚"，不是"省钱工具"**。所有策略（见 4.3 分派策略）都从这个核心思考推导。

### 2.3 分层原则：确定性路径写死，判断性决策放权（v1.8.1）

> **依据**：CrewAI 的「Crews 管自主、Flows 管控制」分层思想（生产 = 外层 Flow 写死路径 + 内层 Crew 自主分工；2026-08-29 笔记）。本体系的对应物早已存在，此处**显式命名**——把隐式结构变成可解释、可传授的原则。

| 层 | 内容 | 为什么 |
|---|------|--------|
| **写死层（确定性）** | failover 链（4.4）+ 命令级表单（4.4.1）+ 批量阈值（≤20 行）+ 限速预算 + **命令级验收标准（4.3.1）** | 可枚举、可验证、不需要临场判断——写死即可靠，不依赖模型发挥 |
| **放权层（判断性）** | 分派策略选傀儡、verify 软失败判定、实质仲裁、最终结论 | 依赖语义理解与上下文，规则写不全——放权给主模型（判断权红线） |

**反面印证**：CrewAI 的「自治路径不可预测」（evermx 独立确认）在关键操作（查账/下单/发通知）上是事故源——本体系傀儡**只执行单一命令、无自主路径**，架构免疫；判断权不外放，**路径决策也不外放**。反面印证二：CrewAI 自承的 token 膨胀坑来自「前环节产出塞进后环节上下文」——本体系是**星型并行**（傀儡互不传递、主模型只收精华），架构上避开链式膨胀；**隐含纪律：不做链式加工**（不把 summarize 结果再喂 tags 再喂 classify），需要多步加工时各步独立取原文、结果并列汇总。

## 四、傀儡管理规范（v1.3 新增，硬约束）

### 1. 准入必测（收编前，v1.7 起含质量考核）
新傀儡进入傀儡池前，**必须体检通过 + 质量考核通过**：
```
python free_models.py health <新模型id>
```
**体检项**：连通性 + classify 功能 + 响应时间。❌ 失败 = 不收编。

**质量考核（v1.7 新增，用户决策 2026-08-23）**：免费 ≠ 能用，**质量差的傀儡收编进来没用，会有副作用**（污染下游判断）。收编前对候选跑 3 类任务各 ≥2 次：
- classify（单条 + 3 行批量）：输出是否纯类别名、逐行对应、无乱码
- tags：输出是否顿号分隔、无乱码（**乱码检测重点**——Qwen2.5-7B 即败于此，3 测 2 乱 `nâ` 前缀）
- summarize：输出是否中文完整、与输入相关

**判定**：任一任务**系统性失败**（乱码/格式错误/答非所问 ≥2 次）→ 质量不达标，**不收编**（不设「限定角色收编」例外——带病傀儡多一条出错路径，靠主模型手工记住禁用任务守不住，2026-08-23 用户否决限定角色先例）；偶发 1 次 → 复测 1 次，仍失败不收编。

### 2. 定期体检（防失效）
**免费模型变动快——可能突然收费、断线、限流收紧。推荐每周体检一次**：
```
python free_models.py health          # 全部傀儡并发体检
python free_models.py health lite     # 单个
```
体检结果自动追加写入 `傀儡健康档案.md`（同目录），历史可查，最新在末尾。

### 3. 记录留档
每次体检自动记录：时间 / 傀儡 / 状态 / 响应时间 / 功能测试结果。**发现 ❌ 的傀儡要立刻处理**（换端点/换 key/移出傀儡池），不能带病使用。

### 4. 并行使用（5 傀儡 = 5 子代理）
5 个傀儡可**同时触发 5 个子代理任务**：
- **WorkBuddy 内**：对话中让我同时跑多个傀儡（我作为编排者并行调脚本）
- **脚本层**：`health` 已内置并发（4 线程）；批量任务可在 WorkBuddy 自动化/子代理中并发调用
- **场景示例**：同一条新闻用 5 个傀儡分别分类（交叉对比）；或 5 个不同子任务分派给 5 个傀儡（并行处理）

## 五、能力总览（14 个命令，v1.7 新增 rate）

> 命令 = 干什么；`--model` = 谁来干。默认模型 glm-4-flash。

### 4.2 选命令口诀

- **判断类**：这文本属于哪类 → classify；难不难 → route；哪个答案对 → **主模型实质仲裁**（低风险批量分歧可选 judge，裁判跨家族）
- **加工类**：太长 → summarize；打标签 → tags；改文风 → rewrite；翻译 → translate
- **理解类**：什么概念 → explain；选哪个好 → proscons；要素有哪些 → extract
- **兜底**：都不沾 → chat
- **管理类**：看傀儡池 → models；体检 → health；评分归档 → rate（v1.7）

### 4.3 编排流程（命令 × 模型，主模型当大脑、傀儡当手）

> **核心逻辑**：`命令` 决定「干什么」，`--model` 决定「谁来干」。读本手册的是**主模型**——它负责理解需求、按傀儡长处分派任务、收集结果、做判断、输出结论；傀儡只执行、不判断、不决策。

**五步编排流程**：

```
① 理解需求   主模型读任务，判断要干什么（选命令）
   ↓
② 分派任务   按傀儡长处选 --model（先 route 评估难度可辅助决策）
   ↓
③ 傀儡干活   并行调 free_models.py，傀儡只执行不判断
   ↓
④ 收集判断   主模型收集结果 → 交叉验证 / 主模型实质仲裁 / 软失败升级检查 / 兜底
   ↓
⑤ 输出结论   不足→回到 ② 重新分派继续干；足够→主模型输出最终结论
```

**分派依据（按傀儡长处）**：

| 场景 | 首选傀儡 | 备选 / 说明 |
|------|---------|------------|
| 长文摘要、结构化任务、复杂改写 | `glm-4-flash` | 128K 窗口，主力 |
| 分类最准、跑题识别 | `agnes-2.5-flash` | 推理模型，deep 档主判 |
| 快速打标、去重摘要 | `agnes-2.0-flash` | 快，省时 |
| 短文本高频轻量 | `lite` | 2 QPS 限速，不参与关键判断 |
| 多模型交叉第三方视角 | `nemotron` | 间歇性上游失败，仅参考 |

**分派策略（省 token 实测推导，2026-08-23；v1.8 增补⑦）**：

| 策略 | 内容 | 依据（实测/研究） |
|------|------|-------------|
| ① 命令按省 token 特征分流 | 输入密集（classify/tags/summarize/route）→ **先瘦身再读**，省 prompt+total 双省；输出密集（extract/translate/explain/proscons）→ **傀儡代写、主模型只采纳**，prompt 倒挂是预期的但 total 仍省 40% | 8 类任务真实计费实测（见 2.1） |
| ② 省 token 量化门槛 | **短文本（<100 字）不加工**，直接主模型读——加工成本 > 收益时不值得 | extract/explain prompt 倒挂（-104%/-115%） |
| ③ 输出密集产出必须主模型校验 | 傀儡输出不能直接当结论（explain 可能脑补、translate 可能错译），主模型做采纳/纠正 | 输出密集 prompt 倒挂 = 主模型读得更多，更要保证质量 |
| ④ 批量任务默认并行分派 | 5 傀儡=5 子代理，主模型只收精华——并行/专注度/防限流比省 token 更根本；**批量分派前按文本同质性分组**（同质内容一组：组内串行、异组并行给不同傀儡）——异质文本混批拉低输出一致性，按关注点分解是编排拓扑的一等优化（分解质量研究：好的分解 2× 吞吐 +35% 成本优势，差的分解拿到互相冲突的结果） | 六维增量价值（见 2.2）+ 2026 编排拓扑研究（v3.0.0 简报 §十） |
| ⑤ 关键判断强制双交叉 | classify 双模型一致才高置信，不一致 → **主模型实质仲裁**（v1.8：读两个候选+必要时原文，直接判哪个正确，不做"A or B"格式题）——异构视角防单模型偏见 | 六维价值第 6 维 + LLM-as-Judge 五大偏差研究（同族裁判溢价 5-25pt / A 位占优 10-15pt，2026-08 扫描） |
| ⑥ 代码任务默认主模型直写（2026-08-23 用户决策） | **只要涉及代码（写/改/修bug/加功能）一律主模型直写，傀儡池不碰代码**——即使长代码任务实测傀儡+校验可省 total 23.5%（deepseek-v4-flash-0731 校准），也不省：代码质量直接决定系统行为，主模型写=一次到位+质量可控，傀儡写需校验+返工，省 23% 不值 | 2026-08-23 编程类实测（bench_coding2.py）：短任务倒挂 -44%~-188%；长代码修bug 傀儡可真省 +23.5%——但决策为质量优先，不采用 |
| ⑦ 软失败升级 verify（v1.8 新增） | A 类判断输出若与预期模式不符（**类别外溢 / 格式可疑 / 边界模糊 / 与已知事实冲突**）→ **不当作成功**，升级主模型重做。failover 管硬失败（退出码/超时/空输出），verify 管软失败（成功返回但答错——静默错误） | cascade verify-then-escalate 范式（LobeHub 417 任务实测：验证便宜时 cascade 稳赚；本体系验证≈免费傀儡 vs 升级主模型，极端价格比天然适合 cascade）；**判据见 4.3.1 命令级验收标准** |
| ⑧ 批量先小规模试跑（v1.8.1 新增） | 批量任务（>20 条 / 预计 >5 轮调用）**先跑 3-5 条样本验证质量，通过再放量**——单条合格 ≠ 批量合格（批量才暴露截断/限流/一致性漂移）；样本不合格 → 换傀儡或分批，**不硬上全量** | glm 23 行截断判例（v1.7：单条正常、23 行截断）；CrewAI 自承坑「大任务先小规模试」；cascade「先验证再放量」同源 |

**判断权归属（红线）**：判断、决策、最终结论**永远属于主模型**。傀儡输出只是参考素材——可交叉验证（两傀儡同任务比对）、可仲裁（**v1.8：默认主模型实质仲裁**；低风险可选 judge 命令，裁判须跨家族）、可兜底（傀儡全挂时主模型亲自执行），但**不因傀儡输出替代主模型判断**（与 MSE v2.8.0「增强不削弱」红线一致）。**输出密集型产出（extract/translate/explain/proscons）一律校验后采纳，不直接引用**。**代码任务（写/改/修bug/加功能）默认主模型直写**（2026-08-23 用户决策，见 4.3 分派策略⑥）——傀儡池无代码能力边界，即使实测长代码傀儡代写可省 token 也不采用，代码质量可控优先。

**典型闭环示例**：主模型收到「判断这条新闻是否利好创业板」→ classify 双交叉（agnes-2.5 + glm）判相关性 → 相关则 summarize 提炼要点 → 主模型综合给出「利好/利空/中性」结论并说明依据。

> 📊 **省 token 实测与六维增量价值已提升为核心章节**：见「二、核心思考与实践」（2.1 实测数据 + 2.2 六维价值）。分派策略 ①-⑧ 均由此推导。

### 4.3.1 命令级验收标准 expected_output（v1.8.1 新增，verify 策略⑦的判据）

> **依据**：CrewAI「Task 必须写 `expected_output`（验收标准），写模糊 AI 会交'差不多的东西'糊弄」。本体系此前只有**结构性自检**（行数对应/非空/截断检测），内容性验收全靠主模型临场感觉——**把判据写出来，verify 才能从"感觉不对"变成"对照验收"**。收编质量考核（§四.1）的三类判据即本表雏形，此处常态化为每次调用可对照的标准。

| 命令 | 验收标准（expected_output） | 结构自检（脚本已实现） | 内容验收（主模型，判软失败） |
|------|--------------------------|:---:|------|
| `classify` | 每条输入恰一行输出；纯类别名（2-5 字）；无解释、无序号、无标点尾巴 | ✅ 行数对应 / 截断检测 | 类别是否在给定集内；**"其他"占比异常高**（类别外溢）即可疑 |
| `tags` | 3-5 个标签；顿号分隔；无乱码、无英文混排 | ✅ 非空 | **乱码**（`nâ` 前缀判例，Qwen2.5-7B 即败于此）；标签是否语义相关 |
| `summarize` | 3-5 句；中文完整；与输入相关 | — | 是否丢关键事实、**是否压缩过度**（2026-08-28 调研 2 分判例：只列表面未抓要点） |
| `extract` | 时间/主体/事件/金额/数字五要素齐全，找不到写"无" | — | **数字是否与原文一致**（最易错）；是否脑补要素 |
| `translate` | 仅译文；无注释无解释；术语前后一致 | — | 数字/专名/单位是否错译；语义是否翻转 |
| `explain` | 大白话；有生活化类比且准确；不引入未解释的新术语 | — | **是否脑补事实**（输出密集最高风险项） |
| `proscons` | 利/弊分列；每档 ≥2 条；每条一句 | — | 是否偏一边（只写利或只写弊）；是否空泛 |
| `rewrite` | 仅输出改写结果；风格符合要求；**语义不变** | — | 是否擅自增删事实、改变原意 |
| `route` | 输出难度（简单/中等/困难）+ 推荐傀儡；格式二段 | — | 难度判定是否与主模型判断相符（判错走 failover，成本低） |
| `judge`（可选档） | 输出 A / B / 一致 + 一句判断依据 | — | **无依据即可疑**（拿不准）；判「一致」需双序确认（v1.8 规则） |
| `chat` | 直接回答；无"作为一个 AI"套话；不自我否定式免责 | — | 是否答非所问；是否与已知事实冲突 |

**用法**：傀儡返回后，先过结构自检（脚本自动），再对照本表做内容验收（主模型，秒级扫一眼）。**任一项不符 → 按策略⑦ 触发软失败升级**，不把可疑输出当成品往下传。判例入调度档案（rate 1-2 分）→ 汇入失败模式注册表。

> **不做的边界**：内容验收**不脚本化**——语义判断交给主模型，脚本只管结构（行数/非空/乱码字符检测可加，性价比高；语义验收脚本化会用正则误伤，且免费模型自评不可靠）。

### 4.4 双保险分级：任务 × failover 链（2026-08-23 用户决策）

> **理念（用户原话）**：双保险不是"每个任务两个模型"，而是"**每个任务有第二条独立失效路径**"——按类分级，不搞一刀切；**A 挂切 B，B 挂切 C**。
> **判据**：失效模式交集越小越真（同平台不同模型免疫模型级失效；跨平台额外覆盖端点/平台级）。层 3 主模型是所有链的终极兜底（C 之后）。

| 类型 | 任务 | failover 链（主→备1→备2） | 切换逻辑 |
|------|------|--------------------------|---------|
| A 关键判断 | classify | agnes-2.5（apihub）→ glm-4-flash（智谱）→ agnes-2.0（apihub） | deep 档双交叉=主判+交叉并行；任一挂→单判→不一致层3主模型 |
| A 关键判断 | route | glm-4-flash（智谱）→ agnes-2.0（apihub）→ lite（讯飞） | 简单文本直接 lite 省时；判错成本低不双交叉 |
| A 关键判断 | judge | **主模型实质仲裁（v1.8 默认，无外部调用故无 failover 链）** | 傀儡 judge 链降为可选省资源档：裁判须与候选跨家族 + 双序跑一致才采纳 |
| B 常规加工 | tags | agnes-2.0（apihub）→ glm-4-flash（智谱）→ lite（讯飞≤8K） | 打标无长文本场景，快优先 |
| B 常规加工 | summarize | glm-4-flash（智谱128K）→ agnes-2.5（apihub）→ agnes-2.0（apihub）→ lite（≤8K） | 长文必须 128K 位 |
| C 改写问答 | rewrite | glm-4-flash（智谱）→ agnes-2.5（apihub）→ agnes-2.0（apihub） | 复杂改写可上推理 |
| C 改写问答 | chat | glm-4-flash（智谱）→ agnes-2.0（apihub）→ lite（讯飞） | 轻量问答快优先 |
| D 输出密集 | translate / proscons / explain / extract | glm-4-flash（智谱）→ agnes-2.5（apihub）→ agnes-2.0（apihub） | **一律主模型校验后采纳**——校验本身即质量第二失效路径 |
| 推理位（重活/交叉） | 困难任务、异构交叉 | agnes-2.5（apihub）→ R1-0528（硅基）→ GLM-Z1（硅基） | **跨平台链**：apihub→硅基，平台级也独立 |
| 兜底位 | 傀儡全挂 | openrouter/free（OpenRouter）→ nemotron-nano（OpenRouter）→ 层3主模型 | /free 自动选可用模型；主模型永不空转 |

**执行纪律**：主模型分派时按链首取，调用失败（退出码非 0 / 超时 / 空输出）→ 自动切链上下一节点，不重试同节点；链尾仍失败 → 层 3 主模型亲自执行。**切换事件与软失败升级（策略⑦ verify）均记入调度档案**（`--group` 归组，rate 补分），为实证调度表攒数据。

**限速感知调度（2026-08-24 落地，依据 §三 限速列）**：RPM/TPM 是调度**约束条件**（防 429），不是质量信号（质量看考核）：
- **批量规模预算**：批量 N 条先算耗时下限 = N ÷ RPM（如 Agnes/OpenRouter 20RPM → 100 条至少 5 分钟；硅基 1000RPM → 秒级）——大批量优先硅基，小批量才走 20RPM 平台
- **TPM 预算**：50K TPM 下 3 万字长文 ≈ 40K token/次 → 每分钟约 1 次，批量长文须排队/分流到多平台
- **429 预判**：RPM 已知的平台，调用前按频率上限 sleep 预排，不靠撞墙重试（脚本现有重试 1 次只作兜底）
- **双交叉注意**：并行双交叉吃 2 个请求配额，20RPM 平台单轮双交叉即占 10% 分钟预算，高频场景错峰或换平台
- **复核**：免费档限速会变，周体检时对照官网复核，变化回写 §三

### 4.4.1 命令级 failover 表单（2026-08-24 落地；v1.8 修订 judge 行 + classify 批量跨族）

**通用切换规则**（所有命令共用）：

| 触发条件 | 动作 |
|---------|------|
| 退出码非 0（API 错误 3 / 配置错误 1） | 切下一节点，**不重试同节点** |
| 超时（>60s 无响应） | 切下一节点 |
| 空输出 / 截断（退出码 3） | 切下一节点（tags 额外：乱码即切，Qwen2.5-7B 判例） |
| 429 限流（脚本重试 1 次后仍失败） | 切下一节点，给该平台记一次限流事件 |
| **软失败（v1.8 新增：成功返回但输出与预期模式不符）** | 不当作成功，按策略⑦升级主模型重做，记入调度档案 |
| 链尾仍失败 | **层 3 主模型亲自执行**（永不空转） |

**命令级表单**（主 → 备1 → 备2；切换事件记入调度档案）：

| 类型 | 命令 | 主 | 备1 | 备2 | 命令级特殊规则 |
|:---:|------|-----|-----|-----|------|
| A | classify | agnes-2.5（apihub，推理主判） | glm-4-flash（智谱，交叉位） | agnes-2.0（apihub） | deep 档双交叉=主+交叉并行；批量>20 行主链改 **agnes-2.5 + Qwen3-8B（v1.8 跨族，同族交叉是伪冗余）**；双交叉一方挂→单判并标注；不一致→主模型实质仲裁 |
| A | route | glm-4-flash（智谱） | agnes-2.0（apihub） | lite（讯飞） | 简单文本直接 lite 省时；判错成本低不双交叉 |
| A | judge | **主模型实质仲裁（v1.8）** | judge 命令可选档：Qwen3-8B（硅基，须与候选跨家族） | — | 主模型直接判哪个正确（实质判断，规避 position bias）；傀儡裁判双序跑一致才采纳，不一致=平局交主模型 |
| B | tags | agnes-2.0（apihub，快） | glm-4-flash（智谱） | lite（讯飞≤8K） | 乱码/空输出立即切备 |
| B | summarize | glm-4-flash（智谱，128K 长文位） | agnes-2.5（apihub） | agnes-2.0（apihub）→lite（≤8K） | 超长文（>5 万字）主模型分块，不硬塞备链 |
| C | rewrite | glm-4-flash（智谱） | agnes-2.5（apihub，复杂改写上推理） | agnes-2.0（apihub） | — |
| C | chat | glm-4-flash（智谱） | agnes-2.0（apihub） | lite（讯飞） | — |
| D | translate / proscons / explain / extract | glm-4-flash（智谱） | agnes-2.5（apihub） | agnes-2.0（apihub） | 输出密集一律主模型校验后采纳（校验=质量第二失效路径） |

**三条差异化规则**：
1. **RPD 不预管理（2026-08-24 用户二修：不查余额、不本地记账）**：免费层无扣费风险，RPD 耗尽的表现就是 429——已由通用切换规则兜底（429 重试 1 次 → 切下一节点 → 层3主模型），无需提前预防；且 RPD 受限平台（OpenRouter 50 RPD）在本体系是低频兜底位，非实际约束，预防成本（每次调度读档案聚合）> 风险损失。**调度只依赖静态能力参数（RPM/TPM/窗口，预加载）+ 运行时反馈（退出码/429/超时/空输出/软失败信号），无预算管理层。**
2. **批量 >20 行 classify 主链跨族覆盖（v1.8 修订）**：glm 不在主链（输出预算不足，截断判例），主链 **agnes-2.5 + Qwen3-8B**——原 agnes-2.5+agnes-2.0 为同族双交叉（Agnes 同族），不提供真异构信号，交叉是伪冗余（Simchi-Levi 定理前提：真异构才有独立信息量）。
3. **超长文 summarize 不走备链**：>5 万字时备链 50K 窗口装不下，直接主模型分块——备链只对 ≤50K 长文有效。

## 六、脚本用法

```bash
# 查看傀儡池
python free_models.py models

# 体检（准入测试 + 定期体检）
python free_models.py health

# 分类（默认 glm-4-flash）
python free_models.py classify "文本内容"

# 分类 + 自定义类别（MSE 相关性判断场景，实测精准）
python free_models.py classify "搜索结果文本" --cats "相关财报,相关公司动态,不相关噪音"

# 指定其他傀儡
python free_models.py classify "文本内容" --model agnes-2.5-flash
python free_models.py tags "文本内容" --model lite

# 长文摘要（管道输入文件，最实用）
python free_models.py summarize < 文章.txt --model glm-4-flash

# 改写
python free_models.py rewrite "原句" "更口语化、带一点轻松感"

# 自由问答
python free_models.py chat "沪深300和创业板指的主要区别？"

# ★ 难度感知路由（v1.4 新增）——评估任务难度 + 推荐傀儡
python free_models.py route "任务文本" [--model lite]   # 默认 glm-4-flash 评估（可靠优先；简单文本 --model lite 省时）
```

### 调度档案（v1.7 新增，W2 调度数据留档）

**原理**：机器记事实、主模型记判断——把「主模型 + 人工口诀」的木偶师进化为「实证调度表」乃至学习式调度的原料（依据 Evolving Orchestration 的训练信号思想，见《Puppeteer范式研究简报_Ver3.0.0.md》§六）。

**自动记录**：每次干活命令（classify/tags/summarize/rewrite/chat/route/judge/translate/proscons/explain/extract）执行后，自动追加一条 JSON 到同目录 `调度档案.jsonl`：

```json
{"type": "dispatch", "ts": "2026-08-23T13:58:51", "task": "classify", "model": "glm-4-flash",
 "text_len": 13, "in_lines": 1, "out_len": 2, "elapsed_ms": 2200, "exit_code": 0, "retry": 0,
 "group": "batch-20260823-新闻分类"}
```

**事后评分**：任务收尾时主模型按任务组补质量分（机器记不了"干得好不好"，这是判断，归主模型）：

```
python free_models.py rate <任务组> <分数1-5> [--note "备注"]
```

口径（v1.8 补全 5 档行为定义，依据 LLM-as-Judge 窄量表+行为锚定研究——模糊分档导致评分不可复现，2026-08-28 调研 summarize 打 2 分即无定义时的拍脑袋判例）：**1=错误输出污染下游 / 2=格式或事实硬伤 / 3=合格 / 4=好 / 5=优**。**失败案例（1-2 分）是调度进化最贵的原料，必须记**。

**失败模式注册表（v1.8 新增，寄生式）**：`调度档案.jsonl` 中 `exit_code≠0` 与 `rate 1-2 分` 的记录即为失败模式原料——**≥50 条聚合实证调度表时，同步聚合《失败模式注册表》（模型 × 任务 × 失败类型三列表）**，把散落判例（Qwen2.5-7B tags 乱码 / 推理模型 content 为空 / 魔搭空壳 / glm 批量截断 / agnes-2.5 长任务空输出）结构化为可查询资产。**不额外造数据**，寄生在日常调度记录上（对齐 Socratic-SWE「解题轨迹即改进原料」思想，轨迹→失败模式的结构化表示）。

**纪律**：批量分派必带 `--group`，任务收尾必 `rate`。不造任务攒数据——寄生在日常使用里。**≥50 条后聚合**出三张表（傀儡×任务型成功率矩阵 / 难度判定命中率 / 成本分布）+ 失败模式注册表，产出《实证调度表》回写本手册 4.3 分派依据，用数据替代口诀。

## 七、v1.4 新增：难度感知路由 + 仲裁（v1.8 修订：主模型实质仲裁为主裁判）

> 依据《Puppeteer范式研究简报》：难度前置路由（成本降 60% 质量仅差 1 分）。仲裁环节 2026-08-28 范式扫描后重设计——依据 LLM-as-Judge 五大具名偏差研究（position/verbosity/self-preference/format/drift，每条有量化效应量与生产级缓解）。

### 1. 难度感知路由（route）

**一句话**：先评估任务难度，再按难度分配傀儡——不浪费 agnes-2.5 在简单任务上，不让 lite 硬扛复杂任务。

```
route "任务文本" [--model lite]   # 难度评估，默认 glm-4-flash（可靠优先；简单文本 --model lite 省时）
```

| 难度 | 推荐傀儡 | 逻辑 |
|------|---------|------|
| 简单 | lite / agnes-2.0-flash | 单点查询、无需推理，低成本快跑 |
| 中等 | glm-4-flash / agnes-2.0-flash | 多步处理、有推理，默认主力 |
| 困难 | agnes-2.5-flash + glm-4-flash（双交叉） | 长文本/复杂推理/模糊目标，需要交叉验证 |

**用法建议**：批量任务先 route 分流，把简单任务全压给 lite（省配额、省时间），困难任务才动用双交叉。

### 2. 仲裁（v1.8 修订：主模型实质仲裁为主）

**一句话**：双模型交叉不一致时，**主模型直接实质仲裁**——读两个候选（必要时回看原文），直接判断哪个正确，**不做"A or B"格式题**。`judge` 命令降为可选省资源档。

**为什么撤掉傀儡裁判（2026-08-28 范式扫描）**：五大偏差中两条正中旧设计——
- **自偏好偏差**（同族溢价 5-25 点）：旧主裁判 glm-4-flash 与候选之一 glm 同族（智谱同源）；MSE 旧安排 agnes-2.0 当裁判与候选 agnes-2.5 同族（Agnes 同源）——**两处都是现存同族偏差**，裁判给同族候选系统性溢价；
- **位置偏差**（A 位占优 10-15 点）：自回归解码的结构性偏差，提示词加"平等考虑两者"实测无效，机制性缓解只有双序跑。

**主模型当裁判的收益**：天然第三方（与池内傀儡无同族关系，自偏好偏差不适用）+ 实质判断规避槽位格式偏差 + 裁判质量最高（8B 级免费小模型裁判能力有限）+ 与「判断权归主模型」红线完全自洽。**代价**：仲裁环节从"傀儡几百 token"变"主模型读几百字候选"——仍远省于主模型读原文重做，judge 的省资源意义从"省 90%"降为"仍省大头"，换来的是简单性与正确性。

**`judge` 命令（可选档，两条硬规则）**：
1. **裁判必须与两个候选跨家族**——候选含 glm → 裁判 Qwen3-8B / lite；候选含 agnes → 裁判 glm / Qwen3-8B；候选含 Qwen3-8B → 裁判 glm / agnes。同族裁判 = 给同族候选 5-25 点溢价。
2. **重要分歧双序跑**——A/B 与 B/A 各一次，两次一致才采纳；不一致 = 平局，交主模型（成本翻倍，但 judge 低频，可接受）。

| 输出 | 含义 | 后续 |
|------|------|------|
| A / B | 判出更优者 | 采用胜者，记录仲裁依据 |
| 一致 | 两候选等价 | 任取其一，或合并 |

**用法建议**：MSE deep 档 agnes-2.5 与 glm-4-flash 分类不一致时，主模型把两个候选分类连同原始文本片段一起看，直接判「这条到底是不是财经」——实质判断，然后按 MSE ⑤.5 处理跑题信号。低风险批量场景可用 judge 命令省资源（跨家族裁判 + 双序）。

## 八、v1.6 新增：翻译 / 利弊 / 解释 / 提取

> 四个新命令，全部实测通过（2026-08-23，glm-4-flash）。

### 1. 翻译（translate）

**一句话**：中英互译——中文进英文出，英文进中文出，其他语言译成中文。

```
translate "The Fed is expected to hold rates steady at the September meeting."
→ 美联储预计将在9月会议上保持利率稳定。
```

**场景**：英文财报/研报/新闻速读；中文内容给英文读者。

### 2. 利弊分析（proscons）

**一句话**：针对主题/选项输出利（优点/收益）与弊（缺点/风险）分列，每条一句。

```
proscons "用定投方式投资沪深300指数基金"
→ 利：分散市场风险，平摊成本，降低单一市场波动影响。
  弊：需要长期坚持，短期市场波动可能造成损失，且需支付一定的管理费和手续费。
```

**场景**：A/B/C 选项对比、决策辅助、投资方式权衡。**注意**：输出为观点参考，不替代你自己的独立判断。

### 3. 通俗解释（explain）

**一句话**：用大白话讲清复杂概念，外行也能听懂，可用生活化类比但必须准确。

```
explain "什么是M2货币供应量"
→ M2货币供应量就像一个大家庭里有多少"钱"可以用来买东西。M2包括家庭、企业、政府等所有人手里的"现金"和可以随时变成现金的东西……
```

**场景**：术语翻译成人话、跨领域概念速懂、给非专业读者讲金融概念。

### 4. 要素提取（extract）

**一句话**：从文本提取结构化要素：时间 / 主体 / 事件 / 金额 / 数字，找不到的写"无"。

```
extract "美联储9月15-16日议息会议预计按兵不动，PCE通胀率今年平均3.5%"
→ 时间：9月15-16日
  主体：美联储
  事件：议息会议
  金额：无
  数字：90%，3.5%
```

**场景**：公告/新闻结构化、事件速览、跨文档要素对比。

## 十、注意事项

1. **体积红线**：lite 单次 ≤1 万字、glm-4-flash ≤10 万字、agnes ≤5 万字、nemotron ≤3 万字，超了脚本自动截断（只处理开头）。
2. **glm-4-flash 限流**：请求体控制在 300KB 内稳定（实测 599KB 触发 429），脚本已设 10 万字余量；高峰期（19-23点）免费模型偶发 429，脚本会重试 1 次，仍失败报错。
3. **讯飞 QPS**：lite 限 2 QPS，批量任务请加间隔（sleep 1）。
4. **agnes 推理特性**：agnes-2.5-flash 是推理模型，响应比 2.0 慢（国内站实测 0.7s），但输出质量更高；追求速度用 agnes-2.0-flash。
5. **不支持工具调用**：脚本是纯文本往返，模型不会执行函数。需要工具能力请走 WorkBuddy 主模型。
6. **模型名**：讯飞只认 `lite`（不要写成 spark-lite）；智谱认 `glm-4-flash`；Agnes 认 `agnes-2.5-flash` / `agnes-2.0-flash`；OpenRouter 用完整 id `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free`。
7. **lite 脑补警示（实测）**：lite 在长文本/模糊输入下有轻微脑补倾向（实测把"马云最近忙啥"脑补成"忙于海外业务扩展"）。**关键判断、事实相关任务一律用 glm-4-flash / agnes**；lite 仅限短文本非关键任务——**难度评估是边界情况，route 默认用 glm-4-flash（可靠优先）；简单文本可 --model lite 省时，复杂文本建议 route 用 agnes-2.0**。
8. **加工不替代判断**：本脚本产出供 Agent 参考，Agent 有最终否决权（与 MSE v2.8.0 增强不削弱原则一致）。
9. **nemotron 模型轮换快 + 间歇性上游失败（v1.4.0 收编）**：OpenRouter 免费模型会突然下架/换名（实测 glm-5.2:free 曾 429）；2026-08-23 实测 7 次调用 4 次报 `Upstream error from Nvidia: ResourceExhausted`（3✅/4❌，上游资源耗尽，免费用户在资源紧张时被优先踢）。**每周体检必须跑**，发现 ❌ 立刻换同名替代或移出；当前仅作交叉测试参考，不参与关键判断。
10. **glm-4.7-flash 收编否决（2026-08-23 体检）**：智谱 glm-4.7-flash 是**推理模型**——内容进 `reasoning_content`（content 为空），思考 16s+（小配额下返回空），max_tokens 2000 时思考 >60s 超时。功能可被 glm-4-flash（0.69s）完全覆盖，**不收编**。
11. **傀儡池只收真免费（2026-08-23 用户决策，2026-08-28 重申）**：消耗魔粒/限时额度的模型一律不收编——qwen-plus/qwen-turbo（阿里百炼限时额度 90-180 天）、Qwen3-Next-80B/DeepSeek-V4-Pro（魔搭魔粒制 2 粒/次）已删除，信息备份至《免费AI模型API接入指南_傀儡池.md》。GLM-5.3 Flash（ox-alpha）2026-08-28 免费通道 404 已死、付费通道评估后**不收编**（用户拍板：不免费的不收编）。**未来收编新傀儡前先核实完整计费规则**（次数免费≠完全免费，警惕魔粒/积分/限时额度等暗扣费）。
12. **编程式调用（v1.6 已修复）**：summarize 输入位置参数优先，subprocess 直接传位置参数即可，不会误读空管道；空输入明确报用法（exit 2）。**judge 偶发"一致"**（模型不确定性，非脚本缺陷），关键分歧直接主模型实质仲裁或换模型对照（详见第六章✅）。
13. **连续调用节流纪律（2026-08-23 实测踩坑）**：批量任务连续调用 8 轮以上会触发 glm-4-flash 限流（429），脚本 `fail()` 抛 `SystemExit` 会静默退出（`except Exception` 捕不到，需 `except BaseException`）。**批量 >5 轮建议：循环间 sleep 2-4s；对 429/5xx 加重试；用 `except BaseException` 捕获傀儡异常**（详见「二、核心思考与实践」2.1 踩坑记录）。
14. **批量分类纪律（v1.7，2026-08-23 实测；v1.8 跨族修订）**：classify 单批 **≤20 行**——根因是**输出预算超限**而非网络问题（45 行/23 行均致 glm-4-flash 截断，glm 长处在 128K 输入、短处恰在输出配额）。长列表批量交叉改用 **agnes-2.5 + Qwen3-8B 跨族组合**（原 agnes-2.5+agnes-2.0 同族双交叉为伪冗余）；glm 的交叉角色限定「长输入→短输出」任务（单条分类/长文摘要）。脚本已内置：多行输入自动注入「逐行分类、行数对应」声明（防合并输出被误判截断）+ 超阈值预检告警。
15. **输出完整性（v1.7）**：classify 多行输入时输出行数 < 输入行数 → 退出码 3 报错（响亮失败，禁止静默截断）；API/截断错误消息统一输出到 stderr（修复 v1.4 起 `fail()` 消息被 SystemExit 静默吞掉的存量问题——失败信息只在 health 备注可见，直调全静默，违反 P1）。
16. **同族裁判禁令（v1.8）**：judge 命令裁判**必须与两个候选跨家族**——同族裁判给同族候选 5-25 点系统性溢价（LLM-as-Judge self-preference 研究），原 glm 裁 agnes+glm、agnes-2.0 裁 agnes-2.5+glm 的安排均为现存同族偏差，已废。重要分歧双序跑（A/B 与 B/A）一致才采纳。
